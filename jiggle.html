Jiggle.

Put Rust, JavaScript, Python and more side by side in one file. Get one native executable back.

Spec0.2.1
Input1 .jgl
Output1 binary

Overview

No build config to babysit.

A project.jgl file contains code blocks in different languages. The compiler, jglc, unpacks them, bundles them as .tar.xz, writes a build.sh for you and produces a single executable.

You never maintain a Makefile, CMake, Gradle or package.json script.

Output

The result is always one file.

01

Single executable

Every language payload is embedded as data, so the output is just jgl_binary (or .exe on Windows).

02

Runtimes stated up front

JVM, .NET and CPython can't be linked in. The program checks for them on launch and tells you what's missing.

03

All or nothing

If one executable can't be produced, jglc stops with an error. No half-built output.

04

Dependencies in one place

One dep[lang] block per language. Jiggle writes each ecosystem's own dependency file.

Syntax

Write blocks, skip the build scripts.

A block is a header followed by { }. Named blocks keep their name; unnamed ones are numbered automatically (v1.lua, v2.lua).

project._jgl {
    target cross
    dep[rs] { serde = "1.0" }
    dep[js] { express = "^4.18.0" }
}

main._rs {
    fn main() { println!("Hello from Jiggle"); }
}

server._js {
    const app = require('express')
    app.listen(3000)
}

.lua {
    print("no name, saved as v1.lua")
}

project._jgl is the manifest and the only ._jgl block the compiler reads.

Pipeline

What happens when you compile.

project.jgl
  → read manifest, resolve imports depth-first
  → parse blocks
  → unpack to a virtual filesystem (lint suppressors added)
  → register custom languages
  → turn dep[lang] into native dependency files
  → bundle project.tar.xz
  → write build.sh
  → compile to jgl_binary
Linker
Rust links when it's present; otherwise clang or gcc.
Windows
--target-win builds jgl_binary.exe using x86_64-pc-windows-gnu.
build.sh
Extracts, restores dependencies, compiles each language and links. --r gives a release build (-O3 -s); debug is the default (-O0 -g). It copies the result to the project root and removes jgl_build/.

Command line

Four commands.

jglc compile  [--project <file>] [--output <dir>] [--bundle-only] [--target-win]
jglc validate [--project <file>]
jglc generate [--project <file>] [--output <dir>] [--target-win]

# shortcuts: build = compile · check = validate · gen = generate

Defaults: project.jgl in, current folder out.

Languages

What it can build today.

KindLanguagesHandling
NativeRust, C, C++, Go, Zig, Nim, FortranBuilt with each native toolchain, then linked.
EmbeddedJavaScript, TypeScript, JSX, TSX, Python, Lua, Ruby, PHP, Shell, BrightScriptTypeScript becomes JS at build time (bun or tsc). The rest are stored as data and run from the executable. BrightScript targets Roku only.
JVM / .NETJava, Kotlin, Scala, C#Built into a JAR or DLL and embedded; the runtime is listed as a requirement.
StaticMarkdown, AsciiDocStored as plain text.
CustomYour own, in the manifestBuilt with the command in a ._sh block.

sh, md, adoc and bs have no package ecosystem, so they can't use dep[lang].

Rules

Edge cases, settled.

Same named block twice
Compiler error. Fix it in the manifest.
Unnamed blocks
Numbered across files; they never clash.
Same dependency twice
Same version is merged. Different versions is an error.
Custom languages
Require a dep.<file> block, even if empty. Built-in extensions are reserved.
Manifest only
dep[lang] anywhere but project._jgl fails to parse.
