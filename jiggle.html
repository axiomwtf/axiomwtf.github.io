Skip the build config.

Jiggle will be deprecated in favor of Poly, a planned build system and package manager for Rust, C/C++ and Go. The Jiggle repo won't be deleted. It will be archived.

A project.jgl file holds code blocks in different languages. The compiler, jglc, unpacks them, bundles everything into a .tar.xz, writes a build.sh and produces one executable.

You don't have to write or maintain a Makefile, a CMake file, a Gradle config or package.json scripts.

You always get one file.

I

Single executable

Each language's code is embedded as data, so the output is just jgl_binary (jgl_binary.exe on Windows).

II

Runtimes up front

JVM, .NET and CPython can't be linked in. The program checks for them when it starts and tells you which ones are missing.

III

All or nothing

If jglc can't produce a single executable, it stops with an error instead of leaving you a half-built result.

IV

Dependencies in one place

Declare them in one dep[lang] block per language and Jiggle writes each ecosystem's own dependency file.

Blocks, not build scripts.

A block is a header followed by { }. Named blocks keep their name. Unnamed ones are numbered automatically (v1.lua, v2.lua).

project._jgl {
    target cross
    dep[rs] { serde = "1.0" }
    dep[js] { express = "^4.18.0" }
}

main._rs {
    fn main() { println!("Hello from Jiggle"); }
}

server._js {
    const app = require('express')
    app.listen(3000)
}

.lua {
    print("no name, saved as v1.lua")
}

project._jgl is the manifest, and it's the only ._jgl block the compiler reads.

What happens when you compile.

project.jgl
  → read manifest, resolve imports depth-first
  → parse blocks
  → unpack to a virtual filesystem (lint suppressors added)
  → register custom languages
  → turn dep[lang] into native dependency files
  → bundle project.tar.xz
  → write build.sh
  → compile to jgl_binary
Linker
Rust does the linking if it's installed. Otherwise it falls back to clang or gcc.
Windows
--target-win builds jgl_binary.exe using x86_64-pc-windows-gnu.
build.sh
Extracts the bundle, restores dependencies, compiles each language and links. --r gives a release build (-O3 -s); debug is the default (-O0 -g). It copies the result to the project root and removes jgl_build/.

Three commands.

jglc compile  [--project <file>] [--output <dir>] [--bundle-only] [--target-win]
jglc validate [--project <file>]
jglc generate [--project <file>] [--output <dir>] [--target-win]

# shortcuts: build = compile · check = validate · gen = generate

By default it reads project.jgl and writes to the current folder.

What it can build today.

KindLanguagesHandling
NativeRust, C, C++, Go, Zig, Nim, FortranBuilt with each native toolchain, then linked.
EmbeddedJavaScript, TypeScript, JSX, TSX, Python, Lua, Ruby, PHP, ShellTypeScript becomes JS at build time (bun or tsc). The rest are stored as data and run from the executable.
JVM / .NETJava, Kotlin, Scala, C#Built into a JAR or DLL and embedded. The runtime is listed as a requirement.
StaticMarkdown, AsciiDocStored as plain text.
CustomYour own, defined in the manifestBuilt with the command in a ._sh block.

sh, md and adoc have no package ecosystem, so they can't use dep[lang].

Edge cases.

Same named block twice
Compiler error. Fix it in the manifest.
Unnamed blocks
Numbered across files, so they never clash.
Same dependency twice
The same version is merged. Different versions are an error.
Custom languages
Need a dep.<file> block, even an empty one. Built-in extensions are reserved.
Manifest only
dep[lang] anywhere except project._jgl fails to parse.
