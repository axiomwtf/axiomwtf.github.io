01 — About

Many languages. One file. One binary.

Jiggle is a polyglot bundle format and compiler. A single project.jgl file holds blocks of code in many languages, and the compiler turns them into one native binary.

Blocks are unpacked into a virtual filesystem, bundled as a .tar.xz, and compiled. The compiler also writes a build.sh for you, so there is no Makefile, CMake config, Gradle build, or package.json script to maintain.

Jiggle is owned by Axiom.

02 — Output

Always exactly one file.

The output is jgl_binary, or jgl_binary.exe on Windows. No JARs, no DLLs, no sidecars, no requires-runtime asterisks.

01

One file

Language payloads are embedded as data segments, so every language the build script handles ends up in one binary.

02

Runtimes declared

JVM, .NET, CPython and similar runtimes can't be statically linked. The binary checks for them at startup and says what to install.

03

Fails loudly

If jglc can't produce one binary, it errors out. It never produces partial output.

04

Deps declared once

One dep[lang] block per language in the manifest. Jiggle generates each ecosystem's native dependency file.

03 — Syntax

Blocks, not build scripts.

Every block has a header and a body in {}. Unnamed blocks are auto-numbered (v1.rs, v2.rs). Named blocks are extracted under their name.

project._jgl {
    target cross

    dep[rs] {
        serde = "1.0"
    }

    dep[js] {
        express = "^4.18.0"
    }
}

main._rs {
    fn main() {
        println!("Hello from Jiggle");
    }
}

server._js {
    const app = require('express')
    app.listen(3000)
}

.lua {
    print("unnamed block, becomes v1.lua")
}

project._jgl is the manifest. It is the only ._jgl block the compiler reads.

04 — Pipeline

From .jgl to binary.

project.jgl
    -> read manifest, resolve imports (depth-first)
    -> parse blocks
    -> unpack VFS (lint suppressors injected)
    -> register custom languages
    -> resolve dep[lang] into native dep files
    -> bundle project.tar.xz
    -> generate build.sh
    -> compile into jgl_binary
Rust compilerWhen Rust is present it acts as the linker. Otherwise clang or gcc does the final link.
WindowsPass --target-win to produce jgl_binary.exe via the x86_64-pc-windows-gnu target.
Build scriptsThe generated build.sh extracts the bundle, restores dependencies, compiles each language, and links. Pass --r for a release build (-O3 -s); default is debug (-O0 -g). After building, build.sh copies the binary to the project root and cleans up jgl_build/.

05 — CLI

Four commands.

jglc compile  [--project <file>] [--output <dir>] [--bundle-only] [--target-win]
jglc validate [--project <file>]
jglc generate [--project <file>] [--output <dir>] [--target-win]

aliases: build = compile, check = validate, gen = generate

Default project file: project.jgl. Default output directory: .

06 — Languages

Supported languages.

The current build script compiles or embeds the languages below into the single binary.

RouteLanguagesHow it's built
NativeRust, C, C++, Go, Zig, Nim, FortranCompiled to objects or archives with the native toolchain, then linked.
EmbeddedJavaScript, TypeScript (precompiled to JS), JSX, TSX, Python, Lua, Ruby, PHP, Shell, BrightScriptTypeScript is precompiled to JS at build time (via bun or tsc). Other languages are embedded as C data segments and run from the binary. BrightScript is meant for Roku targets only.
JVM / .NETJava, Kotlin, Scala, C#Compiled to a JAR or DLL and embedded. The JVM or .NET runtime is declared as a dependency.
Static dataMarkdown, AsciiDocEmbedded as static strings.
CustomDefined in the manifestCompiled with the command given in a ._sh block in the manifest.

Languages with no ecosystem file (sh, md, adoc, bs) cannot take a dep[lang] block.

07 — Rules

Conflicts and edge cases.

Named block clashTwo imported files with the same named block is a compiler error. Resolve it in the manifest.
Unnamed blocksAuto-numbered across files and never conflict.
Dependency clashSame name and version is deduplicated. Same name with different versions is a compiler error.
Custom languagesNeed a dep.<file> block, even when empty. Built-in extensions can't be redefined.
Manifest onlydep[lang] outside project._jgl is a parse error.
