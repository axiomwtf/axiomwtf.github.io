01 — About

One directory in, one verified archive out.

vfsx is a signed, content-addressed virtual filesystem archive format by Axiom. A single directory is packed into a self-verifying `.vfsx.tar.*` file with built-in deduplication, incremental deltas, and Ed25519 signing.

The `.vfsx` in the filename is not just an extension — it's part of the stem: `dir.vfsx.tar.zst`. This distinguishes vfsx archives from plain tarballs. Every archive carries its manifest, content-addressed index, and a signature. Verification is a single command.

It started as a way to make backups you can actually trust — verify the signature, check the hashes, know nothing was tampered with. We build what we want to exist and share it when it's ready.

02 — Format

One file, verified end to end.

The output is always exactly one file: `dir.vfsx.tar.zst` (or `.vfsx.tar.xz`, `.vfsx.tar.gz`). No separate manifest, index, or signature file. Everything lives inside one archive.

01

Signed

Ed25519 signature over manifest and index. Verify with the author's public key.

02

Indexed

Content-addressed manifest + index for random access and hash verification.

03

Deduplicated

Identical files share storage via a global blob store at ~/.cache/vfsx/blobs/.

04

Incremental

Three models: reference+delta, snapshot chains, and global blob store.

vfsx create ./project -o project.vfsx.tar.zst  # first run generates your key
vfsx key export -o mykey.vfsx                    # share this
vfsx verify project.vfsx.tar.zst --key mykey.vfsx # anyone checks your archive

Zstandard compression by default. Pass --xz or --gz to switch.

03 — Incremental

Three models, one workflow.

Each model serves a different need — pick what fits.

ModelCommandHow it works
Reference + Deltavfsx create --base base.vfsx.tar.zstDelta archive references base by hash. Only changed/new files stored in delta.
Snapshot Chainvfsx create --base previous.vfsx.tar.zstEach archive carries parent_hash. Extraction replays chain automatically.
Blob Storevfsx create ./dirGlobal content-addressed store. Identical files across archives share storage.

04 — Keys

Sign on first run.

Run vfsx create and it generates your Ed25519 identity at ~/.config/vfsx/keys/. Export the public key as a .vfsx file for others to verify your archives.

Generatevfsx key gen [--force] — creates identity.pub and identity.priv
Exportvfsx key export -o mykey.vfsx --owner "alice@laptop" — valid vfsx archive with pubkey + metadata
Importvfsx key import mykey.vfsx — imports pubkey for verification
Verifyvfsx verify archive.vfsx.tar.zst --key mykey.vfsx — checks signature + content hashes

05 — CLI

Six subcommands.

vfsx create [DIR] -o OUTPUT [--zst|--xz|--gz] [--level N] [--base BASE] [--threads N]
vfsx extract ARCHIVE [-C DIR] [--verify] [--no-overwrite]
vfsx list ARCHIVE [--json] [--long] [--xattrs]
vfsx verify ARCHIVE --key KEY.vfsx [--strict] [--hashes-only]
vfsx key gen [--force]
vfsx key export [-o OUTPUT] [--owner STRING]

aliases:
  x = extract
  ls = list
  v = verify
  k = key

Default directory: .. Default compression: zstd level 3 with threads = CPU count.
