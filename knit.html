A version control system and a from-scratch alternative to Git.

knit keeps the entire repository - history, working-tree state, remotes, keys - inside a single append-only .knit file. There is no staging area: knit tie snapshots the working tree directly.

The vocabulary is yarn: commits are knots, branches are strands, merges are joins, conflicts are snags, clones are pickups.

One file, append-only, crash-tolerant.

I

One file

The whole repo - objects, strands, marks, stashes, hubs, stat cache - is a single .knit file. No sidecars.

II

Content-addressed

Blobs, trees and knots are addressed by blake3 over canonical encodings.

III

Crash-safe

CRC-protected frames, a torn tail is ignored, and flock on the file itself is the only lock.

IV

Git-compatible

Trees, blobs and modes map onto Git's object model, so import is a translation, not a redesign.

knit cast-on [dir]              # create a yarnball
knit tie -knot "title" -yarn "description"   # snapshot the working tree
knit count                     # what changed since the last knot
knit rows                      # the knots on this strand

Ignore rules live in .noyarn files, in gitignore syntax.

Every knot is signed.

Each knot carries an Ed25519 signature over its canonical encoding, published as a KEY record the first time it signs. knit pick verifies the signature against the yarnball's known keys.

Cast on
knit cast-on [dir] creates the yarnball
Tie
knit tie -knot "title" -yarn "body" snapshots the tree; knot and save are aliases
Join
knit join <strand> merges; conflicts become snags you resolve and tie
Pick
knit pick <knot> shows the message, diff and signature status
Loom
knit loom <strand> <dir> checks out a strand into a separate, read-only directory
Block
knit block compacts the yarnball, keeping only reachable objects

Git import today, GitHub without git.

knit pickup reads Git repositories directly - loose objects and packfiles with OFS/REF delta chains - preserving modes, symlinks and commit IDs. Annotated tags become marks.

Hubs sync yarnballs over ssh through the knits stdio daemon, or to GitHub through gh api: blobs, trees and commits as JSON, never a git binary.

CommandWhat it does
knit pickup <path>Import a git repo (worktree, .git dir, or bare)
knit hub add github.com/o/rRegister a remote; urls also accept file paths and user@host
knit send <hub>Push the yarnball (and, on GitHub, the source tree)
knit gather <hub>Pull new objects, keys, marks and strands
knit haul <hub>Gather, then join the remote head strand
